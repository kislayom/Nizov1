Agent Architectures — OpenClaw · Hermes Agent · Nizo

CTO-level comparison · architecture, trade-offs, and where to plant the flag.

TL;DR

  • OpenClaw = a platform. Skills + MCP + subagents. Cloud-LLM-shaped, dev-loop-optimized. Steal: skill format, MCP wiring, subagent isolation.
  • Hermes Agent = a kernel. ~300 LOC of "while-loop with tool calls". Steal: loop shape, Hermes-2-Pro tool grammar.
  • Nizo = a product. Plain Java, local-first, streaming-native, condense-aware, per-user memory. Owns its stack top-to-bottom.
  • Nizo's bet: a small surface that composes the strongest ideas from both, without inheriting the cloud-API or Python-ecosystem coupling.

Positioning

OpenClaw

Claude-Code-style local agent for terminal devs. Skills as the unit of capability.

Optimizes for

  • Dev inner-loop (file edit → test → iterate)
  • Skill reusability across projects
  • Multi-agent decomposition via Task tool
  • Cloud-LLM economics (Claude / OpenAI)

Pays cost in

  • Cloud-LLM dependence (price, latency, privacy)
  • TS/Python heterogeneity at runtime

Hermes Agent

Reference impl for Hermes-2-Pro tool-calling. Minimum viable agent loop.

Optimizes for

  • Clarity — read it in 30 minutes
  • Distribution alignment with Hermes-2-Pro models
  • Acting as a substrate others build on

Pays cost in

  • No memory, no skills, no channels — DIY everything
  • Deliberately not a platform

Nizo

Production personal agent. Local Qwen3.6-27B, plain Java 21, owns the stack.

Optimizes for

  • Local execution (data sovereignty, $0 marginal cost)
  • Cross-session, cross-channel persona via per-user memory
  • Streaming UX end-to-end (SSE, sealed events)
  • Long-horizon: condense + reflect + skills

Pays cost in

  • Single-GPU constraint shapes model choice
  • Build-everything-yourself cost (compensated by tight surface)

What to steal · what to avoid

Steal

  • Skill format (MD + YAML frontmatter) — done
  • MCP both directions — pending
  • Subagent isolation via Task — pending
  • Pre/post-tool hooks — partial (condense only)

Avoid

  • Cloud-LLM coupling baked into core types
  • Two-language runtime (TS + Python)
  • npm dep tree as part of deploy story

Steal

  • Single-loop simplicity — done in AgentLoop
  • Hermes tool-call grammar awareness — done (llama-server --tool-call-parser hermes)
  • Tools as plain callables, no framework — done

Avoid

  • Stateless turns (we need persistence)
  • No memory/skills story (we need both)
  • "Library not platform" stops short of product

Strengths to lean into

  • Streaming end-to-end with sealed events
  • Per-user memory injection (not a tool)
  • Local model means $0 marginal experimentation cost
  • Tight Java 21 surface — fast iteration

Gaps to close

  • Subagents · MCP · reflection loop · scheduler · Telegram
  • Real tokenizer (not 3.5 chars/token heuristic)
  • Test coverage on agent core

Why Nizo plants its flag here

  • Local-first wins on long-horizon agents. Agents that remember get expensive on cloud APIs (every turn re-bills the system + memory). A 256k-context local model with prompt-cache reuse makes per-user memory architecturally cheap.
  • Java 21 is the right runtime for agent infra. Sealed types make event streams safe; virtual threads make per-channel concurrency free; uber-jar makes deploy boring; cold start beats Node + Python.
  • Tight surface beats wide surface. Hermes proves you don't need much loop. OpenClaw proves you do need a real platform around it. Nizo aims at the intersection — minimal core, deliberate platform around it.
  • Condense is non-negotiable. Without it, every long session degrades. We built it before we needed it; OpenClaw added it later; Hermes leaves it to you.
  • Per-user memory is a system property, not a tool. Tools the model can forget to call don't make a persona. Injecting memory at every turn does.

What to do next (90-day view)

  1. Month 1 — close the platform gap. Subagents (Task-style isolated workers) · MCP client + server · pre/post-tool hooks. Steal directly from OpenClaw's surface.
  2. Month 2 — close the quality gap. Real Qwen tokenizer (replace 3.5 chars/token) · auto-archive on condense (recoverable) · validator with retry · JUnit tests on core paths.
  3. Month 3 — long-horizon UX. Reflection loop (post-turn → save_skill) · scheduler (cron + NL reminders) · Telegram resurrection · semantic file/skill reinjection (use nizo-memory embeddings).
